# GreenSim — путеводитель по коду для новичка

> Документ относится к ветке `agent/greensim-p0-stabilization`. Он описывает фактическую структуру исходников на момент создания. Это справочник, а не исполняемый код: он не меняет игру и не должен подключаться в браузере.

## 1. С чего начать

GreenSim — браузерный симулятор тепличного хозяйства. В проекте разделены три основные ответственности:

1. **Модель мира** — расчёт времени, растений, климата, света, воды, удобрений, урожая, рынка, склада, кампании и денег.
2. **Отображение** — отрисовка теплицы на Canvas, камера, геометрия растений и обработка попаданий мышью/пальцем.
3. **Интерфейс** — меню, вкладки, магазин, параметры, обучение, сохранения, события, кнопки и главный цикл.

Главное правило разработки: если меняется формула игры, сначала ищите её в `parts/core.js`; если меняется внешний вид сцены — в `parts/render.js`; если меняются панели и поведение кнопок — в `parts/ui.js`; если меняется внешний вид HTML/CSS — в `parts/head.html`.

## 2. Карта файлов

| Файл | Назначение | Когда редактировать |
|---|---|---|
| `index.html` | Готовая страница, которую открывает браузер и публикует GitHub Pages | Обычно не редактировать вручную: это собранный файл |
| `parts/head.html` | HTML-разметка, метаданные, все CSS-стили, верхняя часть документа | Новые HTML-блоки, классы, цвета, размеры, адаптивная вёрстка |
| `parts/core.js` | Чистое ядро симуляции: данные мира и игровые расчёты | Формулы, баланс, урожай, климат, рынок, кампания, покупки |
| `parts/render.js` | Canvas, камера, 3D-проекция, геометрия и отрисовка сцены | Ракурсы, визуальные объекты, световой слой, клики по растениям |
| `parts/ui.js` | Состояние интерфейса, обработчики, панели, меню и цикл приложения | Кнопки, экраны, обучение, настройки, сохранения, звук |
| `parts/tail.html` | Закрывающие теги `script`, `body`, `html` | Почти никогда |
| `build.sh` | Собирает `index.html` конкатенацией пяти частей и проверяет JS | Менять только при изменении порядка сборки или проверок |
| `manifest.webmanifest` | Имя, иконки, стартовый адрес и режим установки PWA | Настройки установки приложения |
| `sw.js` | Service Worker: сетевой кэш и запуск офлайн | Правила обновления и офлайн-кэширования |
| `.github/workflows/pages.yml` | Автоматическая публикация GitHub Pages | Ветка публикации и шаги CI/CD |

### Важное отличие исходников от сборки

Сейчас `index.html` — актуальная запускаемая версия, а `parts/*` — модульная структура проекта. В рабочей ветке они не полностью совпадают по содержимому. Не запускайте `build.sh` и не заменяйте `index.html` результатом сборки без предварительного сравнения: это может затереть изменения, которые пока находятся только в готовом файле. Перед изменением архитектуры сначала синхронизируйте части и сборку отдельной задачей.

## 3. Как устроен запуск игры

1. Браузер загружает `index.html`.
2. Внутри страницы подключены CSS, разметка и JavaScript.
3. `parts/core.js` (в готовом файле — его собранный эквивалент) объявляет каталоги культур, профили, параметры и функции модели.
4. `parts/render.js` получает Canvas `#scene`, настраивает камеру и умеет рисовать сцену.
5. `parts/ui.js` создаёт меню и панели, читает сохранение, запускает `requestAnimationFrame(frame)`.
6. При старте новой игры `startGame()` создаёт объект `world` через `makeWorld()`.
7. Функция `frame()` регулярно обновляет модель через `stepWorld()`, перерисовывает интерфейс и вызывает `drawScene()`.
8. События интерфейса меняют параметры мира, после чего интерфейс обновляет отображаемые значения и сохраняет игру.

**Поток данных:** действие игрока → обработчик UI → функция ядра → изменение `world` → `renderAll()` / `renderTop()` → изображение и показатели на экране.

## 4. Ядро симуляции — `parts/core.js`

Ядро намеренно не должно зависеть от HTML и DOM. Оно работает с объектом мира и возвращает данные/результаты. Благодаря этому его проще проверять отдельно и использовать для прогноза.

### 4.1. Главные каталоги и настройки

| Имя | Что хранит |
|---|---|
| `CFG` | Базовая геометрия теплицы, длительность сезона, цены энергии/воды/удобрений/CO₂, труд и ограничения роста |
| `CROPS` | Каталог культур: параметры роста, листьев, плодов, температуры, плотности посадки, цены и срока хранения |
| `CROP_LIGHT` | Световые ориентиры для каждой культуры: DLI и длина фотопериода |
| `DIFFICULTY` | Коэффициенты сложности: постоянные расходы, аварийность, цены, дрейф датчиков и погодные события |
| `PROFILES` | Типы хозяйства и стартовые условия: деньги, площадь, цена продукции, расходы, оборудование и кредитный лимит |
| `WH` | Параметры склада: объём секции, предел секций, объём хранения материалов, аренда и стоимость расширения |
| `GROW_SYS` | Системы выращивания: грунт, кокос, DWC, NFT и аэропоника; коэффициенты воды, питания, урожая и риска |
| `SOIL` | Начальная влажность, пороги сухости/увядания/перелива и размер дозы ручного полива |
| `NET` | Упрощённая экономика дополнительных филиалов тепличной сети |
| `GEAR`, `EQUIP_DEFS`, `WARRANTY` | Оборудование, его свойства, цена, установка и гарантийные правила |
| `CHAPTERS`, `MAILBOX` | Главы кампании, условия сюжетных писем и варианты ответов |
| `MISSIONS` | Задания/цели, которые игрок может выполнять в течение сезона |
| `AUTO_KEYS`, `AUTO`-настройки мира | Доступные виды автоматизации и расписания |

| `PRICE_SEASON`, `MONTHS`, `DOY_IN_MONTH` | Сезонность рынка и календарные преобразования |
| `SAVE_VERSION` | Версия структуры сохранения для миграций |

Числа в каталогах — балансные параметры. Изменение одного значения может повлиять на экономику, скорость роста или доступность механики. Перед изменением ищите все места использования имени через поиск по репозиторию.

### 4.2. Основные поля объекта мира `world`

`world` — центральное состояние одного игрового сезона. В нём находятся:

- **Время:** `day`, `hour`, `doy`, `season`, `seasons`, `seed`.
- **Стартовые условия:** `profile`, `crop`, `diffId`, `site`, `weather`, `orient`, `area`.
- **Экономика:** `money`, `startMoney`, `revenue`, `cost`, `debt`, `rep`.
- **Растения:** `plants`, `harvestedKg`, `harvest`, `history`, `moist`.
- **Среда:** `env`, `meas`, `drift`, `realWeather`, `power`.
- **Управление:** `ctrl` (уставки и переключатели), `auto` (расписания автоматизации).
- **Ресурсы:** `stock`, `wh` (склад), `has` (купленное оборудование).
- **Кампания:** `camp`, `mail`, `story`, `missions`, `tutorialEnabled`, `tutorialStep`.
- **Журнал и итоги:** `log`, `incidents`, `over`, `carry`.

Это ориентир по основным полям, а не закрытая схема: модель развивается, и отдельные подсистемы добавляют поля в процессе игры. Не удаляйте неизвестное поле из сохранения без анализа миграции и сериализации.

**Экономика филиалов**

**Рынок, себестоимость и продажи**

## 5. Отрисовка — `parts/render.js`

Рендер отвечает за визуальную сцену. Он не должен менять экономику или выращивание: его задача — представить уже рассчитанный мир.

### Основные переменные
- `canvas` — HTML-элемент сцены `#scene`.
- `ctx` — 2D-контекст Canvas, через который рисуются линии и заливки.
- `W`, `H` — текущая ширина и высота холста в CSS-пикселях.
- `DPR` — коэффициент плотности пикселей экрана.
- `cam` — состояние камеры: режим, поворот `yaw`, наклон `pitch`, дистанция `dist`, масштаб `zoom`, выбранное растение `plant`, точка фокуса `target` и инерция `vel`.
- `CAM_HOME` — исходное положение камеры.
- `PITCH_MIN`, `PITCH_MAX` — границы наклона.
- `CAM_FLOOR_Y` — нижний предел высоты камеры.
- `camTween` — промежуточное состояние плавного перехода.
- `dataLayer` — включён ли слой освещённости.
- `_halftonePat` — кэш узора полутоновой заливки.
- `_view` — подготовленная проекция текущего ракурса.
- `VESSEL` — параметры геометрии ёмкости.

### Функции рендера
- `resize` — подгоняет Canvas под размер окна и DPR.
- `ensureSize` — проверяет, не изменился ли размер контейнера.
- `camPreset` — готовит параметры стандартного ракурса.
- `camTo` — задаёт плавный переход камеры.
- `camStep` — обновляет переход или инерцию камеры на каждом кадре.
- `camPan` — перемещает точку взгляда.
- `heatColor` — переводит величину освещённости в цвет шкалы.
- `selPlant` — возвращает выбранное растение.
- `buildView` — строит параметры текущей проекции.
- `nodeYw` — получает мировую высоту узла растения.
- `liftTarget` — корректирует точку камеры при взгляде снизу.
- `persp` — строит параметры перспективной проекции.
- `refreshView` — пересоздаёт кэш проекции.
- `project` — переводит мировую 3D-точку в координаты экрана.
- `depthOf` — возвращает глубину точки для сортировки.
- `poly` — рисует многоугольник.
- `line3` — рисует линию в мировых координатах.
- `dot3` — рисует точку/маркер.
- `skyColor` — выбирает цвет неба.
- `drawBackground` — рисует фон и окружение.
- `leafColor` — выбирает цвет листа.
- `drawScene` — основной рендер теплицы и растений.
- `vesselGeom` — формирует геометрию горшка/ёмкости.
- `soilColor` — выбирает цвет грунта с учётом влажности.
- `vesselMouth` — рисует верхнее отверстие ёмкости.
- `drawVessel` — рисует ёмкость целиком.
- `lampSpots` — рассчитывает/рисует световые пятна.
- `hitTest` — ищет объект сцены под координатой указателя.
- `organInfo` — собирает данные для карточки выбранного органа.
- `pointInPoly` — проверяет, находится ли точка внутри многоугольника.

### 8.3. Как работают медиазапросы

- Базовые стили применяются к широкому экрану.
- `@media (max-width:1180px)` переводит интерфейс в планшетную компоновку.
- `@media (max-width:720px)` включает мобильную компоновку: верхняя строка компактнее, боковые панели становятся выдвижным листом, снизу появляется док.
- `@media (max-width:420px)` дополнительно уменьшает отступы и подписи для узких телефонов.
- Правила, расположенные ниже в CSS, могут переопределять более ранние. Поэтому при поиске причины размера элемента проверяйте все упоминания его селектора, а не только первое.


### 8.5. Структура колонок дашборда и панели рисков

Внутри `#dashGrid` левая колонка `.col.left` должна содержать четыре самостоятельные панели в таком порядке:

1. `[data-p="climate"]` — датчики и ручное управление климатом.
2. `[data-p="why"]` — диагностика причин отклонений.
3. `[data-p="risks"]` — предупреждения и раскрываемые действия (`#alerts`).
4. `[data-p="finance"]` — показатели экономики (`#finance`).

Каждая панель закрывается до начала следующей. Все четыре панели являются соседними дочерними элементами `.col.left`; нельзя вкладывать экономику внутрь рисков или размещать риски непосредственно в `#dashGrid`. Ошибка в одном закрывающем `</div>` меняет количество grid-колонок и на телефоне может привести к тому, что блок рисков окажется поверх Canvas теплицы.

На телефонах (ширина до 720 px) левая колонка скрыта и показывается как выдвижной лист через нижний док. Вкладка «Климат» включает панели `climate` и `risks`, поэтому при открытии она показывает обе панели внутри одной шторки. Стили `.col.left`, `.panel.sel`, `body.sheet-open` и логика `SHEET_TABS.phone` в `parts/ui.js` должны оставаться согласованными.

При изменении HTML дашборда проверяйте:
- у всех четырёх панелей одинаковый уровень вложенности;
- `#alerts` находится внутри панели `data-p="risks"`;
- `#finance` находится внутри панели `data-p="finance"`;
- ни одна панель левой колонки не является непосредственным grid-элементом `#dashGrid`;
- на мобильной ширине вкладка «Климат» открывает риски в выдвижном листе, не перекрывая сцену в закрытом состоянии.


### 8.6. Настройка панелей левой колонки

Панели `climate`, `why`, `risks` и `finance` имеют общий заголовок `.panel-head`:
- кнопка `.panel-fold[data-fold-target]` сворачивает или раскрывает содержимое;
- кнопки `[data-panel-move="up"]` и `[data-panel-move="down"]` меняют порядок;
- `.panel-body` содержит полезное содержимое панели и скрывается через атрибут `hidden`.

Параметры хранятся отдельно от игрового сохранения в localStorage под ключом `vg_dashboard_panels_v1`: `order` — массив ключей панелей, `collapsed` — объект признаков сворачивания. При недоступности localStorage используются исходный порядок и раскрытое состояние.

Логика в `parts/ui.js`: `readDashboardPrefs` и `writeDashboardPrefs` читают/записывают настройки; `applyDashboardPanelOrder` применяет порядок; `saveDashboardPanelOrder` сохраняет перестановку; `bindDashboardDetails` подключает сворачивание, перемещение и подсказки датчиков.

CSS в `parts/head.html` распределяет высоту гибко: панели делят доступное пространство, свёрнутые занимают только место заголовка, а длинное содержимое прокручивается внутри панели. Для новой панели задайте уникальный `data-panel-key`, кнопку `data-panel-fold` + `data-fold-target`, контейнер `.panel-body` с уникальным ID и две кнопки перемещения.

### 8.4. Как безопасно менять стиль

1. Найдите селектор элемента по ID или классу, например `#camBar` или `.panel`.
2. Проверьте все повторные правила для этого селектора.
3. Изменяйте минимальное число свойств: `padding`, `gap`, `font-size`, `width`, `max-height` и т. п.
4. Проверяйте desktop, планшет и телефон: один медиазапрос может перекрыть другой.
5. Не используйте глобальные селекторы вроде `button` для точечной правки одной панели — задавайте более точную область, например `#center .camPanel button`.
6. Не удаляйте `pointer-events`, `z-index`, `position`, `overflow` и `transform` без проверки: они влияют на клики, слои, прокрутку и выдвижные панели.

## 9. Настройки игры — что меняют

Настройки строятся функцией `renderSettings()` в `parts/ui.js`. Карточки создаются в HTML-шаблоне, а затем привязываются к `world.ctrl` или другим объектам состояния.

### 9.1. Разделы настроек

- **Погода:** климатические нормы или архив реальной погоды по выбранной локации.
- **Выращивание:** система выращивания; досветка и экраны; DLI; рецепты питания и EC/pH.
- **Автоматизация:** таймеры света, полива, CO₂ и полный автопилот. Доступность зависит от главы кампании и купленного оборудования.
- **Интерфейс:** камера, валюта и установка PWA.
- **Обучение и справка:** словарь терминов, обзор интерфейса, обучение кампании, справка о модели.
- **Сохранение и сезон:** параметры текущего сезона, экспорт/импорт, сохранение, удаление и перезапуск.

### 9.2. Уставки и переключатели

| Ключ в `world.ctrl` | Значение |
|---|---|
| `heatSet` | Температурная уставка отопления |
| `ventSet` | Температурная уставка проветривания |
| `co2Set` | Целевая концентрация CO₂ |
| `ecSet` | Целевая электропроводность питательного раствора |
| `phSet` | Целевой pH раствора |
| `recipe` | Выбранный рецепт питания |
| `lampEnabled` | Включена ли досветка |
| `alarmOn`, `alarmFrom`, `alarmTo` | Будильник досветки и временное окно напоминания |
| `screenOn` | Включён ли термоэкран |
| `shadeOn` | Включена ли затеняющая сетка |

Важное различие: **уставка** — желаемое значение автоматики, **ручной переключатель** — фактическое включение оборудования, **автоматизация** — отдельное расписание/правило, которое может менять состояние в течение игрового времени. Не объединяйте эти три понятия в одну переменную.

### 9.3. Полезные технические термины

- **DLI** — суммарное количество света, полученное растением за сутки.
- **PPFD** — мгновенная плотность потока фотосинтетических фотонов.
- **LAI** — индекс листовой поверхности.
- **EC** — электропроводность раствора, косвенный показатель концентрации растворённых солей.
- **pH** — кислотность/щелочность раствора.
- **Fertigation** — подача воды и удобрений вместе.
- **PRNG / seed** — генератор случайных чисел и начальное значение, позволяющее повторять сценарий.
- **Canvas** — область браузера, в которой сцена рисуется программно.
- **Service Worker** — фоновый браузерный скрипт, который управляет сетевым кэшем и офлайн-режимом.

## 10. Сохранения и безопасность данных

- Сохранение сериализуется функцией `serializeWorld()` и восстанавливается через `deserializeWorld()`.
- Версия формата обозначается `SAVE_VERSION`. Если меняется структура `world`, проверьте совместимость старых сохранений.
- Не удаляйте неизвестные поля из `world`: они могут использоваться переносом между сезонами, прогнозом, кампанией или миграцией.
- `carrySnapshot()` и `applyCarry()` отвечают за перенос хозяйства между сезонами. Изменения этих функций влияют на продолжение кампании.
- Экспорт/импорт файла сохранения реализован в UI, но формат данных принадлежит ядру.

## 11. Как добавить новую функцию

1. Определите слой: модель, рендер, UI или стили.
2. Если это новое правило игры — добавьте расчёт в `parts/core.js`, не обращаясь к DOM.
3. Если нужен новый показатель — добавьте вывод в соответствующую функцию `render...` в `parts/ui.js`.
4. Если нужна кнопка — добавьте HTML-элемент с уникальным ID и назначьте обработчик в UI.
5. Если меняется внешний вид — добавьте CSS рядом с тематической группой и учтите мобильные медиазапросы.
6. Если новое значение должно сохраняться — проверьте `serializeWorld()`, `deserializeWorld()`, версию сохранения и перенос сезона.
7. Если параметр влияет на прогноз — убедитесь, что `cloneWorld()` и функции прогноза учитывают его.
8. Проверьте синтаксис JS, запуск новой игры, продолжение сохранения и адаптивность интерфейса.

### 8.7. Читаемые подсказки климатических датчиков

Подсказки датчиков и климатических регуляторов показываются в общем плавающем слое `#sensorTooltip`, который создаётся функцией `bindDashboardDetails` в `parts/ui.js`. Слой имеет фиксированное позиционирование и добавляется непосредственно в `document.body`, поэтому его не обрезают прокручиваемые контейнеры панелей. Положение рассчитывается относительно выбранной подписи с учётом границ окна: при нехватке места снизу подсказка открывается сверху.

На компьютере подсказка показывается при наведении или фокусе клавиатуры; по клику закрепляется до повторного клика, клика вне подписи или нажатия Escape. На сенсорном экране используется тот же клик. Контент берётся из атрибута `data-tip`. Стили читаемости и позиционирования находятся в `parts/head.html` в селекторе `#sensorTooltip`.

## 8.7. Пролог кампании — письмо тёти Розы

Перед настройкой и запуском новой кампании игрок видит модальное окно `#campaignPrologue`. Это не системное описание режима, а личное письмо тёти Розы, оставленное на кухонном столе.

- Разметка письма находится в `parts/head.html`; готовая страница собирается в `index.html`.
- Обработчики `campaignPrologueBack` и `campaignPrologueContinue` находятся в `parts/ui.js`: возврат ведёт в главное меню, продолжение открывает стандартную настройку кампании.
- В письме Роза объясняет отъезд намёками на тёплое место, длинные дни и срочное задание. Географию и истинную причину отъезда текст не раскрывает.
- Поручение игроку: присматривать за квартирой, цветами и котом. Кот упоминается как будущий персонаж; письмо не создаёт его в игровом мире и не меняет механику.
- Балконное хозяйство служит естественным переходом к обучению климату, датчикам, поливу, питанию, покупкам и экономике.
- Визуальные классы `.letter-sheet`, `.letter-meta`, `.letter-body` и `.letter-sign` оформляют текст как отдельное письмо; на узких экранах уменьшается размер шрифта.

## 8.13. Экономика магазина: лёгкая сложность и балконные фасовки

- В `parts/core.js` параметры `DIFFICULTY.*.shopF` отвечают только за цены покупок: лёгкая сложность — ×0,80, обычная — ×1,00, жёсткая — ×1,10. Они не смешиваются с `fixedF` (постоянные расходы) и `priceF` (цена продажи урожая).
- `shopPriceFactor(w)` возвращает множитель магазина для текущего мира. `shopItemCost(w,it)` — единая функция итоговой цены с учётом профиля, индивидуальной цены товара и сложности. Её используют и `buyItem`, и `renderShop`, чтобы отображаемая цена совпадала со списанием.
- Ремонт также учитывает множитель сложности; при страховке скидка применяется до множителя сложности.
- В группе «Доступно для дома и балкона» цены приведены к бытовому и полупрофессиональному масштабу: цифровой термогигрометр, небольшие ловушки, клип-вентиляторы, карманный EC/TDS-тестер, компактная фитолента, плёнка и малый обогреватель.
- «Малые фасовки для балкона» содержат удобрение 2 кг, воду 1 м³, семена 10 шт и препараты по 100 мл. Они открыты с главы «Балкон».
- Большие партии удобрений, воды, семян и стандартные обработки от вредителей/гнили открываются с главы «Комната», чтобы балконный игрок не покупал промышленные объёмы.
- В `parts/ui.js` коэффициент сложности показан в карточке выбора уровня и в верхней строке магазина. Новые ID товаров добавлены в `GEAR`; логика эффектов существующих покупок не меняется.
- Проверки цен и доступности добавлены в `test7_story.js`; `test_lib.js` экспортирует `shopPriceFactor` и `shopItemCost` для тестов.

### 8.14. Пропуск обучения, климат в шапке и камера

- В панели обучения кампании кнопка «шаг →» вызывает `skipTutorStep`: пропускает только текущую инструкцию, записывает `world.tutorialStep` и сохраняет состояние.

## 8.15. Стартовая скорость симуляции

- Новая игра (`startGame()` в `parts/ui.js`) начинает симуляцию на скорости `1×`: `speed = 1`.
- После перехода к следующему сезону (`startNextSeason()`) скорость также сбрасывается на `1×`.
- Активная кнопка панели скорости синхронизируется с `data-s="1"`, чтобы интерфейс не показывал `4×` при фактической скорости `1×`.
- Ускорение можно включить вручную кнопками панели; автоматическое ускорение при запуске больше не применяется.


## 8.16. Скорость при продолжении сохранения

- `applyLoadedWorld()` в `parts/ui.js` вызывается при выборе «Продолжить» и при загрузке файла сохранения.
- После восстановления мира функция явно сбрасывает скорость симуляции на `1×` (`speed = 1`).
- Индикатор панели `.spd` также переключается на кнопку `data-s="1"`, чтобы отображаемая скорость совпадала с фактической.
- Скорость не наследуется из значения по умолчанию при открытии страницы и не восстанавливается из старого сохранения.
