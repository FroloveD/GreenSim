# Проверки и две ветки — короткая шпаргалка

## 1. Одна команда — все автопроверки

Linux / macOS / Git Bash:

```
./test_all.sh --fast
```

Windows PowerShell (из папки с игрой):

```
.\test_all.ps1 --fast
```

Скрипт сначала делает `bash build.sh` (чтобы `index.html` не отстал от `parts/*`), потом гоняет раннер. Если хоть одна проверка упала — код возврата 1, и это видно в консоли словами `ПРОВАЛЕНО: N`.

Флаги:

| команда | что делает | время |
|---|---|---|
| `node tools/run_all.js` | всё, включая 90-дневные прогоны | ~4 мин |
| `node tools/run_all.js --fast` | без долгих прогонов | ~3 мин |
| `node tools/run_all.js --no-browser` | только Node, браузер не нужен (для CI) | ~15 с |
| `node tools/run_all.js --browser-only` | только Playwright | зависит от набора |

Перед первым браузерным прогоном один раз:

```
npm i playwright-core @sparticuz/chromium
```

Сервер на `:8080` раннер поднимает сам (`tools/serve.js`) и гасит в конце — руками ничего запускать не надо.

## 3. Ветки: работаем в `dev`, публикуем из `main`

`dev` — рабочая ветка **и то, что публикуется на сайте**: в `pages.yml` стоит `branches: [ dev ]`.
`main` держим как проверенный снимок для отката. Автопроверки (`tests.yml`) бегут на обе ветки.

Пушим изменения:

```
git checkout dev
git add -A
git commit -m "что сделали"
git push origin dev
```

Первый раз на новой машине — с привязкой ветки: `git push -u origin dev`.

Релиз-снимок в `main` (по желанию, для отката):

```
git checkout main
git merge dev
git push origin main
```

После пуша в `dev` на GitHub сами зеленеют два job'а: `build` (сверяет `index.html` со сборкой из `parts/*`)
и `deploy` (Pages). Сайт: https://froloved.github.io/GreenSim/

## 4. Досветка: что изменилось

- Кнопка **«Досветка»** под сценой включает и выключает свет при любой лампе (лента, лампа на стойке, LED) — раньше она требовала именно LED за 2800 € и врала «купите».
- **Клик по светильнику в сцене** тоже переключает: светильники видны всегда, когда лампа куплена (тёмный корпус = выключена, тёплый = горит), наведение показывает карточку с состоянием.
- «Параметры» и кнопка под сценой идут через одну функцию, поэтому не расходятся; состояние попадает в сохранение.
- Теплица больше не остаётся тёмной при одной ленте: сцена считает свет как «лампа или лента».

## 5. Таймеры и будильник

- «Параметры» → карточка **«Таймеры и автоматизация»**: свет по расписанию, полив по датчику (с целью влаги), CO₂ по окну, полная автоматизация.
- Свободный сезон — всё сразу. Кампания открывает по шагу: глава 1 свет → глава 2 полив (только грунт/кокос) → глава 3 CO₂ (нужен клапан) → глава 4 полная автоматизация (нужен климат-контроллер).
- Ручная кнопка «Досветка» сильнее расписания: нажали — таймер света выключился.
- Будильник досветки теперь виден: строка в панели рисков (она сортируется, плохое вперёд) и всплывающее напоминание раз в сутки. Сам лампу не переключает.

## 6. Полив: что изменилось

- Влажность субстрата видна в панели датчиков («влага 55 %») — это показание датчика, оно может врать и калибруется.
- Кнопка **«Полить 55 %»** под сценой: одна доза +15 п.п., вода списывается из бака (18 л на балконе, 1,8 м³ на теплицу 400 м²).
- **Клик по горшку** в сцене поливает грядку; грунт темнеет от воды, карточка под курсором показывает влагу и дозу.
- Сухо ниже 32 % — водный стресс и минус к урожаю (без полива 1006 кг против 1330 кг за 60 дней); перелив выше 88 % — корневая гниль. Оба состояния видны алертами и оба устранимы.
- Автополива нет: только руки игрока, напоминают алерты.

## 7. LED-панель и надёжное сохранение (раунд 8)

**Панель.** Магазин → «Свет» → «LED-панель 420 µmol», 760 €, доступна с первой главы (балкон).
`lampPPFDOf` возвращает 420 (лента 60/90, лампа на стойке 90, LED 190/280), `lampPowerKW` — не меньше
0,15 кВт на м². В сцене панель — сплошная плита под коньком (четыре точечных светильника остаются для лент и ламп),
клик по ней переключает свет, карточка показывает 420 µmol. Старые сейвы без флага `has.panel` открываются как раньше.

**Сохранение.** `localStorage` остаётся быстрым слоем, копия пишется в IndexedDB (`greenhouse` / `saves` / `current`).
Если `localStorage` пуст, а в IndexedDB есть запись — сезон восстанавливается из неё (`restoreFromIdb`).
Кнопка «Удалить» стирает обе копии и сразу убирает баннер «Продолжить сезон».
Уровень доступа виден в «Параметрах»: `работает` / `недоступна` / `заблокирована`.

**Числа.** Дроби в интерфейсе — через запятую (`nf`), прочерк вместо `NaN`, единицы с пробелом (`17,5 ч`,
`1,98 € в час`), цена часа досветки считается из `CFG.energyPrice`, а не из литерала.

**Проверки:** `tools/test_idb.js` (10 проверок в браузере — запись, переживание очистки `localStorage`,
удаление обеих копий) и раздел 7–8 в `tools/test_season2.js` (13 проверок панели и формата чисел).

## 8. Буфер остывания светильника (раунд 9)

**Что меняется.** Свет и тепло от лампы больше не появляются мгновенно: `lampGlow` (доля света) и `lampWarm`
(доля тепла) идут к цели экспонентой с постоянной `lampTauMin(w)` — лента 5 мин, вторая лента 6,
лампа на стойке 15, LED 20, LED с бустом 22, панель 420 — 40. Свет разгоняется за τ/8 и гаснет за τ/24,
тепло — за τ/2 и остывает за τ.

**Что видно.** Карточка светильника: «корпус: остывает 86%», «тепло от корпуса +0,52 кВт, остынет за ~114 мин»,
«свет» считается по фактическому glow. Панель климата: строка «лампа» с остатком тепла в кВт.

**Что важно.** Электричество списывается по номиналу сразу (буфер счётчик не отменяет), тепло приходит
в воздух с задержкой. Теплоёмкость воздуха (`tauT`) намеренно не менялась: даже ×1.05 роняет зимний балкон
у нижнего клампа −8 °C и ломает проверку зимнего снаряжения.

**Проверки:** `tools/test_lampbuffer.js` — 24 проверки без браузера (τ по лампам, разгон/спад, тепло против света,
температура двух миров, счётчик, DLI, мигание, миграция сейва, клон мира). Набор — 23 файла.

## 9. Скриншоты проверок — без жёстких путей

Раньше в браузерных проверках путь был вписан руками (`/home/user/shots/60_before_reload.png`), и на Windows
`check_save.js` и `check_topfit.js` падали на сохранении кадра. Теперь есть `tools/paths.js`:

```js
const { shotFile } = require('./paths');
await cdpShot(page, shotFile('60_before_reload.png'));   // <корень репозитория>/shots/60_before_reload.png
```

`shotFile` считает корень от `__dirname`, сам создаёт папку `shots/` и работает на любой ОС.

## 10. Квартальные счета за свет и тепло (раунд 10)

**Как это работает.** Свет и тепло не списываются каждый час: `w.util.qKwhHeat/qKwhLamp` копят киловатт-часы,
счёт выставляется 1 января, апреля, июля и октября (`UTIL.billDoy`), плюс закрывающий счёт в конце сезона.
Неоплаченный счёт даёт пени 0,1% в день, на 360-м дне просрочки (4 квартала) — суд и судебные издержки
(15% долга, минимум 40 €), на 720-м (8 кварталов) — банкротство с распродажей.

**Где смотреть.** «Экономика» → блок сверху: «в счёт: свет, тепло N €» или сумма счёта с кнопкой «Оплатить».
«Риски» — предупреждение о просрочке. Отчёт сезона — строка «Счёт за свет и тепло». Экран банкротства —
отдельный модал с остатком на руки.

**Проверки:** `tools/test_util.js` — 39 проверок без браузера. Два старых теста сверки денег учитывают
начисленное, но не оплаченное. Набор — 24 файла.
