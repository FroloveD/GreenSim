# Проверки и две ветки — короткая шпаргалка

## 1. Одна команда — все автопроверки

Linux / macOS / Git Bash:

```
./test_all.sh --fast
```

Windows PowerShell (из папки с игрой):

```
.\test_all.ps1 --fast
```

Скрипт сначала делает `bash build.sh` (чтобы `index.html` не отстал от `parts/*`), потом гоняет раннер. Если хоть одна проверка упала — код возврата 1, и это видно в консоли словами `ПРОВАЛЕНО: N`.

Флаги:

| команда | что делает | время |
|---|---|---|
| `node tools/run_all.js` | всё, включая 90-дневные прогоны | ~4 мин |
| `node tools/run_all.js --fast` | без долгих прогонов | ~3 мин |
| `node tools/run_all.js --no-browser` | только Node, браузер не нужен (для CI) | ~15 с |
| `node tools/run_all.js --browser-only` | только Playwright | зависит от набора |

Перед первым браузерным прогоном один раз:

```
npm i playwright-core @sparticuz/chromium
```

Сервер на `:8080` раннер поднимает сам (`tools/serve.js`) и гасит в конце — руками ничего запускать не надо.

## 2. Что именно проверяется

| файл | что ловит |
|---|---|
| `tools/test_sync.js` | `index.html` собран из `parts/*` (забытый `./build.sh`), синтаксис скрипта |
| `tools/test_core.js` | ядро без браузера: 12 комбинаций по 60 дней, бухгалтерия «деньги = выручка − расходы», склад, детерминизм прогноза, покупки, досветка |
| `tools/check_lamp.js` | **новое:** кнопка «Досветка» и клик по светильнику в сцене, синхронность с «Параметрами», отказ без лампы, сохранение света |
| `tools/check_light.js` | лента вместо «не куплена», ручной режим без автоматики, будильник только напоминает |
| `tools/check_money.js`, `check_co2gate.js` | копейки, баки, задания без оборудования |
| `tools/check_save.js`, `check_new.js` | сохранение и загрузка, новый сезон |
| `tools/check_campaign.js`, `test3_dom.js`, `check_layout.js`, `check_topfit.js` | кампания целиком, 90 дней в заглушках DOM, раскладки планшет/телефон, шапка в строку |

Одиночный прогон любого файла: `node tools/check_lamp.js` (сервер `:8080` должен быть занят — его поднимает `run_all` или `node tools/serve.js`).

## 3. Отдельно в `dev`, отдельно в `main`

`dev` — работа и эксперименты, GitHub Pages на неё **не реагирует** (в workflow стоит `branches: [main]`). `main` — только проверенное, её публикует сайт.

Только эксперименты:

```
git checkout dev
git add -A
git commit -m "что сделали"
git push
```

Первый раз на новой машине — с привязкой ветки: `git push -u origin dev`.

Публикация на сайт (когда в `dev` всё зелёное):

```
git checkout main
git merge dev
git push origin main
```

После `push` в `main` в Actions должны позеленеть две галочки: `build` и `deploy`. Сайт: https://froloved.github.io/GreenSim/

Если упало — новый коммит, а не «Re-run»: повтор создаёт второй артефакт `github-pages` и деплой падает навсегда, пока не почистишь.

Мелкие правила, чтобы не наступать на те же грабли:

- по одной команде на строку — PowerShell не понимает `::` и `&&` из bat-примеров;
- комментарии в консоль не копировать;
- если локальная ветка называется `Dev`, переименовать: `git branch -m Dev dev`, иначе на GitHub появятся две ветки, различающиеся регистром.

## 4. Досветка: что изменилось

- Кнопка **«Досветка»** под сценой включает и выключает свет при любой лампе (лента, лампа на стойке, LED) — раньше она требовала именно LED за 2800 € и врала «купите».
- **Клик по светильнику в сцене** тоже переключает: светильники видны всегда, когда лампа куплена (тёмный корпус = выключена, тёплый = горит), наведение показывает карточку с состоянием.
- «Параметры» и кнопка под сценой идут через одну функцию, поэтому не расходятся; состояние попадает в сохранение.
- Теплица больше не остаётся тёмной при одной ленте: сцена считает свет как «лампа или лента».
