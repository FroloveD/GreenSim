## Находки по приоритету

### P1 — HTML-инъекция через импортируемое сохранение

**Файлы:**
- `parts/core.js`, `deserializeWorld()`, около строки 2572.
- `parts/ui.js`, `loadFromText()`, около строки 296.
- `parts/ui.js`, `renderContracts()`, около строки 1162.
- `parts/ui.js`, `renderMail()`, около строки 1188.
- `parts/ui.js`, `openMail()`, около строки 1214.
- `parts/ui.js`, `renderLog()`, около строки 1231.

**Наблюдение:** импортируемый JSON разбирается и проверяется на наличие верхнеуровневых `pack.world` и поддерживаемой версии, но поля вложенного мира не проходят полноценную проверку схемы. Затем значения из мира (например, записи журнала, тема/текст писем и данные контрактов) попадают в HTML-шаблоны через `innerHTML`.

**Риск:** специально подготовленный файл сохранения может содержать HTML-разметку и обработчики событий. При импорте и отображении таких данных браузер может выполнить внедрённый код в origin игры. Это также может привести к повреждению интерфейса некорректными структурами данных.

**Рекомендация:**
1. Считать любой импортируемый save недоверенным вводом.
2. Валидировать структуру и типы всех массивов/объектов, диапазоны чисел и допустимые ID до присвоения `world`.
3. Выводить пользовательские/сохранённые строки через `textContent` и создание DOM-узлов, а не интерполяцией в `innerHTML`.
4. Если HTML-шаблоны остаются, экранировать все значения данных централизованной функцией; не полагаться только на проверку версии save.
5. Добавить тест с вредоносными строками в `log`, `mail` и `contracts`: после импорта они должны отображаться как текст и не создавать исполняемых элементов.

### P1 — Автотесты не запускаются при обычном push в рабочую ветку

**Последствие:** прямой push в рабочую ветку запускает Pages workflow, но не гарантирует запуск `tools/run_all.js`. Последний успешный run 46057425895 — это именно **Deploy to GitHub Pages**, а не workflow «Автопроверки». Его успех подтверждает сборку/публикацию, но не прохождение тестов ядра и Playwright.

**Рекомендация:** добавить `agent/greensim-p0-stabilization` в push.branches workflow `tests.yml`. Сохранить запуск на pull_request и workflow_dispatch. После изменения проверить, что на один push появляются оба независимых workflow: Pages и Автопроверки.

### P2 — Исправление скорости при продолжении не закреплено регрессионным тестом

**Файлы:**
- `parts/ui.js`, `applyLoadedWorld()`.
- `tools/check_save.js`, около строки 41.
- `tools/check_campaign.js`.

Исправление в `applyLoadedWorld()` действительно устанавливает `speed = 1` и синхронизирует кнопку `.spd[data-s="1"]`. Но тест сохранения после нажатия «Продолжить» проверяет день, баланс, культуру и структуру растения — не проверяет фактическое значение `speed` и активную кнопку скорости. Проверка в `check_campaign.js` относится к началу новой кампании, а не к восстановлению сохранения.

**Рекомендация:** дополнить `check_save.js`: сразу после «Продолжить» зафиксировать `speed === 1`, активную кнопку `data-s="1"` и отсутствие активных кнопок других скоростей. Дополнительно проверить импорт JSON-файла сохранения.

### P3 — В одном тесте есть утверждение, которое всегда считается успешным

**Файл:** `tools/test_sync.js`.

Проверка, предназначенная для контроля количества блоков script, заканчивается выражением `|| true`. Поэтому она всегда сообщает успех независимо от результата условия.

**Рекомендация:** удалить `|| true` и сделать проверку содержательной либо убрать её, если проверка уже полностью покрыта синтаксическим тестом.

### P3 — Ошибка догоняющей симуляции при загрузке скрывается

**Файл:** `parts/ui.js`, `applyLoadedWorld()`.

Вызов `catchUp()` обёрнут в пустой `catch(e){}`. Если при догоне возникнет ошибка из-за повреждённого/неполного сохранения, она будет проглочена, после чего интерфейс попытается продолжить работу с уже присвоенным миром.

**Рекомендация:** показывать диагностическое сообщение, сохранять исходный пакет до успешной миграции/догоняющей симуляции и не оставлять приложение в частично восстановленном состоянии.

## Что уже выглядит технически организованным

- Чёткое разделение: `core.js` — модель, `render.js` — Canvas, `ui.js` — интерфейс, `head.html` — HTML/CSS.
- Единая сборка из частей и проверка синхронности `index.html`.
- В ядре есть детерминированный PRNG, тесты на матрицу профилей/культур, бухгалтерию, склад, полив, досветку, таймеры, прогноз, перенос сезона, рынок и погоду.
- Есть Playwright-набор для сохранений, кампании, интерфейса, климата и PWA.
- PWA использует network-first для навигации и fallback на кэш для офлайн-запуска.
- В текущем HEAD: `index.html` совпадает с конкатенацией частей; собранный JavaScript синтаксически корректен.
